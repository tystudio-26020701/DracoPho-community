# Руководство пользователя Mark Shot

Это руководство описывает повседневную работу с Mark Shot: основное внимание
уделено функции **выбора окна / компонента при наведении курсора** (при
перемещении мыши автоматически подсвечивается окно под курсором; щелчок
выбирает его), процессу аннотирования, безоконному захвату и настройке.

> Документация в этом репозитории создана в сообщественном форке и зеркалируется
> в вышестоящие и корпоративные репозитории. Корпоративная редакция добавляет
> отдельный раздел для своего локального MCP-сервера.

---

## 1. Быстрый старт

### 1.1 Запуск

Начните сеанс захвата области:

```bash
mark-shot
```

Нажмите горячую клавишу рабочего стола (см. § 8) или запустите из терминала.
На активном дисплее открывается замороженный полноэкранный оверлей. Перемещайте
мышь, чтобы нарисовать прямоугольник выделения, затем отпустите кнопку, чтобы
войти в редактор аннотаций.

### 1.2 Переносимые сборки

Если вы используете переносимый комплект (`mark-shot-upstream`, `mark-shot-community`,
`mark-shot-enterprise`), запускайте его с помощью встроенного лаунчера, чтобы
были найдены встроенные библиотеки Qt, плагины и вспомогательные скрипты:

```bash
portable/mark-shot-community/bin/run-mark-shot.sh
```

Лаунчер добавляет свой каталог `bin/` в `PATH` — это требуется для
вспомогательных скриптов определения окон (`mark-shot-window-detection-*`) и
помощников OCR / загрузки.

## 2. Выбор окна / компонента при наведении курсора

Mark Shot может определять окна текущего рабочего стола до того, как вы
выберете область. Пока оверлей выделения открыт, **перемещение мыши подсвечивает
окно под курсором** бирюзовой рамкой. **Обычный левый щелчок (без перетаскивания)
выбирает всё окно** как область захвата; затем его можно сразу аннотировать,
скопировать, закрепить или сохранить.

Подсвечиваемые окна берутся из скрипта определения, зависящего от композитора,
который выполняется до появления оверлея:

| Рабочий стол | Источник определения | Примечания |
| :--- | :--- | :--- |
| GNOME Wayland | встроенное расширение Shell `mark-shot-scroll-helper@snemc.org` через D-Bus | требуется включённое расширение (см. § 2.1) |
| KDE Plasma Wayland | одноразовый KWin-скрипт через `qdbus6` / `qdbus` + journalctl | требуется сеанс KWin |
| Hyprland | `hyprctl -j clients` | |
| niri | `niri msg -j windows` + разбор конфигурации | |
| X11 | внутрипроцессный перебор XCB по `_NET_CLIENT_LIST_STACKING` | скрипт не нужен |
| Windows | внутрипроцессный `EnumWindows` | скрипт не нужен |

Отслеживаются только **окна верхнего уровня**. Отдельные виджеты внутри окна
(«компоненты») не раскрываются Wayland-композиторами, поэтому выбор при
наведении на всех платформах нацелен на целые окна.

### 2.1 GNOME Wayland: включение вспомогательного расширения

```bash
gnome-extensions enable mark-shot-scroll-helper@snemc.org
```

Проверьте, что D-Bus-помощник отвечает:

```bash
gdbus call --session \
  --dest org.gnome.Shell \
  --object-path /org/gnome/Shell/Extensions/MarkShotScrollHelper \
  --method org.gnome.Shell.Extensions.MarkShotScrollHelper.Version
# -> ('5',)
```

Если вызов не удаётся, выйдите из системы и войдите снова (или перезапустите
GNOME Shell на X11) и повторите попытку. Без расширения вспомогательный скрипт
GNOME завершается с ошибкой, и выбор при наведении остаётся выключенным
(обычный выбор перетаскиванием по-прежнему работает).

### 2.2 Как это использовать

1. Запустите захват (`mark-shot` или горячая клавиша рабочего стола).
2. Не нажимая кнопок мыши, наведите курсор на окно. Бирюзовая рамка
   обводит окно, которое будет выбрано.
3. **Щёлкните один раз** (нажмите и отпустите, не сдвинувшись более чем на
   несколько пикселей), чтобы выбрать это окно. Если окна перекрываются,
   побеждает самое верхнее окно под курсором (с учётом z-порядка).
4. После отпускания открывается редактор аннотаций с точно окантованным окном.
5. Чтобы выделить **вручную**, просто перетащите прямоугольник как обычно —
   рамка наведения игнорируется, как только перетаскивание превышает порог
   щелчка.

Подсветка наведения отключается, пока активен стартовый инструмент Цветовая
пипетка (`C`) или Линейка (`R`), и остаётся доступной в стартовых режимах
Сканер кода (`Q`), захвата дисплея (`D`) и записи GIF / видео.

### 2.3 Выбор окон на правильном мониторе

Определение окон выполняется для каждой цели захвата. В конфигурации с
несколькими мониторами каждое замороженное окно получает только те окна, которые
пересекаются с его собственной геометрией, поэтому рамка наведения совпадает с
тем, что вы видите на этом дисплее.

### 2.4 Включение / отключение

Функция включена по умолчанию (`windowDetection.enabled = true`). Переключите её
в **Настройки → Дополнительно → Window Detection Enabled**, или отредактируйте
`~/.config/mark-shot/config.json`:

```json
{
  "windowDetection": {
    "enabled": true,
    "command": "mark-shot-window-detection-gnome",
    "timeoutMs": 1000,
    "env": {}
  }
}
```

- `command`: скрипт определения. На GNOME / KDE / Hyprland / niri Wayland
  соответствующий вашему сеансу встроенный скрипт `mark-shot-window-detection-*`
  выбирается автоматически; на X11 и Windows платформа перечисляется
  внутрипроцессно, и `command` можно оставить пустым. **Пользовательская
  команда (например, абсолютный путь) всегда учитывается.**
- `timeoutMs`: максимальное время ожидания скрипта (100–30000 мс, по умолчанию 1000).
- `env`: дополнительные переменные окружения, передаваемые скрипту. Специфичные
  для композитора настройки (смещения) описаны в заголовках скриптов.

### 2.5 Устранение неполадок

| Симптом | Проверка |
| :--- | :--- |
| Нет бирюзовой рамки на GNOME Wayland | включено ли расширение? вызов `gdbus` выше должен вернуть версию |
| Нет бирюзовой рамки на X11 / Windows | ничего — перечисление платформы встроено; убедитесь, что сеанс захвата не использует стартовый инструмент указателя |
| Рамка наведения выбирает не то (нижнее) окно | отсутствуют данные z-порядка в пользовательском скрипте определения; окна без `zOrder` ранжируются как нижний слой |
| Захват запускается медленно | скрипт определения выполняется до оверлея; поднимайте `timeoutMs` только если рабочий стол медленный, или установите `enabled:false`, чтобы пропустить его |
| Посмотреть диагностику | запустите `mark-shot --debug --debug-log /tmp/mark-shot.log`; ищите строки `window-detection` |

## 3. Выбор области и стартовые инструменты

До фиксации области можно использовать инструменты стартового оверлея:

| Горячая клавиша | Инструмент | Поведение |
| :---: | :--- | :--- |
| `C` | Цветовая пипетка | Взять пробу пикселя; колесо изменяет размер лупы; левый щелчок открывает панель цвета (форматы HEX / RGB / HSL / HSV / Qt); правый щелчок или `Esc` — выход |
| `R` | Линейка | Наведение считывает координаты пикселя; левое перетаскивание измеряет прямоугольник с шириной, высотой, диагональю и площадью; правый щелчок или `Esc` — выход |
| `Q` | Сканер кода | Перетащите область вокруг QR-кода / штрихкода; расшифрованный результат открывается в окне с возможностью копирования |
| `D` | Захват дисплея | Захватывает все выходы, обрезает по дисплеям, показывает миниатюры с наведением (копировать / редактировать / сохранить) |
| `S` | Остановить активную запись GIF / видео | останавливает запись, показанную в оверлее |

`Esc` отменяет сеанс; правый щелчок (без стартового инструмента) также отменяет.

## 4. Инструменты аннотирования

После выбора области (или открытия локального изображения) открывается редактор
с панелью аннотаций. Инструменты переключаются цифровыми клавишами или с панели
инструментов:

| Горячая клавиша | Инструмент | Описание |
| :---: | :--- | :--- |
| `V` | Перемещение / Панорамирование | переместить всё выделение, панорамировать холст локального изображения |
| `S` | Выделение | выбрать, переместить, масштабировать, повернуть, удалить существующие аннотации |
| `P` | Перо | плавные штрихи от руки |
| `L` | Линия | прямые линии |
| `H` | Маркер | полупрозрачный маркер; стиль от руки или прямой линии |
| `R` | Прямоугольник | рамка со стилями `Stroke` / `Highlight` / `Invert`, скруглённые углы |
| `E` | Эллипс | эллипс / круг |
| `A` | Стрелка | классические стрелки (с оперением, KDE, двунаправленные) |
| `T` | Текст | форматированный текст; колесо или ползунки изменяют размер; диагональные ручки масштабируют обе стороны, боковые ручки регулируют перенос; точный размер в pt, семейство шрифта, жирный / курсив на панели шрифта |
| `N` | Номер | последовательные нумерованные маркеры (арабские, буквенные, римские, китайские, …) |
| `M` | Мозаика | акриловое морозное размытие для скрытия конфиденциального содержимого |
| `G` | Лазер | временные штрихи, исчезающие автоматически |

Советы по рисованию:

- Удерживайте `Ctrl` при рисовании прямоугольника / эллипса, чтобы ограничить
  форму квадратом / кругом.
- Прокручивайте колесо, пока активен инструмент, чтобы регулировать толщину
  штриха, размер текста, масштаб номера или размер блока мозаики (живой
  предпросмотр).
- В режиме `Select` прокрутка приближает холст, а удержание средней кнопки
  панорамирует; двойное нажатие `Ctrl` сбрасывает.

### 4.1 Редактирование существующей аннотации

Переключитесь на **Select** (`S`). Щёлкните аннотацию, чтобы показать её ручки:

- перетащите внутрь, чтобы переместить;
- перетащите угловые / боковые ручки, чтобы изменить размер;
- перетащите круглую ручку над верхним краем, чтобы повернуть;
- нажмите `Delete` / `Backspace`, чтобы удалить;
- двойной щелчок по тексту редактирует его на месте.

Панель свойств (справа) редактирует выбранную аннотацию: цвет, толщину, стиль,
семейство шрифта текста / размер / жирный / курсив. Несколько аннотаций можно
выбрать, перетащив рамку выделения в режиме инструмента `Select`; затем группу
можно перемещать, масштабировать, поворачивать и удалять вместе.

### 4.2 Действия

| Сочетание | Действие |
| :--- | :--- |
| `Ctrl+C` | копировать в буфер обмена |
| `Ctrl+S` / `Enter` | сохранить (шаблон пути из настроек) |
| `Ctrl+P` | закрепить как плавающее окно-стикер |
| `Ctrl+U` | загрузить на настроенный хостинг изображений; URL копируется |
| `Ctrl+Z` / `Ctrl+Y` | отменить / повторить |
| `F` | переключить область захвата (выделение ↔ полный экран) |

### 4.3 Экспортная рамка

Включите **Настройки → Экспорт → Mac-style frame**, чтобы добавить прозрачные
поля, скруглённые углы и мягкую тень к сохраняемым / копируемым / загружаемым
изображениям.

## 5. Закреплённые окна-стикеры

| Жест / Сочетание | Поведение |
| :--- | :--- |
| левое перетаскивание | переместить стикер |
| колесо | масштабировать пропорционально |
| двойной левый щелчок / `Esc` | закрыть |
| правый щелчок | контекстное меню (повернуть, увеличить, поверх всех окон, копировать текст, перевести, сохранить, копировать, закрыть) |

OCR-текст внутри закреплённого окна можно выделять и копировать (`Ctrl+C` /
контекстное меню). Перевод (совместимая с OpenAI конечная точка) отображает
переведённый текст обратно на изображении в исходных позициях макета.

## 6. Прокручиваемый скриншот

1. Выберите область (или используйте плавающую ручку перетаскивания для очень
   больших областей).
2. Оверлей прокручивает целевое окно; захваченные кадры сшиваются в
   длинное изображение.
3. На GNOME Wayland требуется расширение Mark Shot Scroll Helper (§ 2.1).

Прокручиваемый захват готов к продакшену на niri и аналогичных композиторах
wlroots/Wayland; на KDE, X11 и других стеках это тестовая функция. Если она не
работает, используйте обычные скриншоты или пользовательскую команду расширения.

## 7. Безоконный захват (CLI)

Неинтерактивный захват записывает PNG и выводит JSON:

```bash
# основной экран
mark-shot --capture-to /tmp/shot.png

# каталог (имя файла с меткой времени)
mark-shot --capture-to /tmp/shots/

# область
mark-shot --capture-to /tmp/r.png --region 0,0,1280,720

# конкретный дисплей, с курсором
mark-shot --capture-to /tmp/w.png --display DP-1 --include-cursor

# несколько дисплеев сразу (по одному PNG на каждый)
mark-shot --capture-to /tmp/shots/ --display DP-1 --display DP-2

# список выходов
mark-shot --list-displays
```

Все безоконные опции взаимоисключающие с позиционным файлом изображения.
Полную таблицу аргументов см. в README.

### 7.1 Безоконный захват окна / компонента

Mark Shot может захватывать **конкретные окна — или компонент (подобласть)
внутри окна — без открытия какого-либо интерфейса**, из скрипта, конвейера
сборки или агента. Процесс завершается, как только изображения записаны или
возвращены; он никогда не создаёт окно, никогда не показывает диалог и никогда
не крадёт фокус, поэтому пользователь может продолжать работать, пока
инструмент захватывает рабочий стол.

Сначала выведите список окон, чтобы увидеть, что доступно:

```bash
mark-shot --list-windows
```

Пример вывода (GNOME Wayland):

```json
{"count":2,"platform":"wayland","source":"compositor-script","windows":[
  {"index":0,"id":"0x3c00007","title":"Mark Shot - VSCodium","class":"codium","instance":"codium","x":1920,"y":0,"width":1680,"height":1050,"zOrder":1},
  {"index":1,"title":"Terminal","class":"org.gnome.Terminal","x":67,"y":32,"width":800,"height":600}
]}
```

Каждая запись содержит поля, по которым сопоставляются селекторы: `index`, `id`
(идентификатор окна X11 / идентификатор, предоставленный бэкендом), `title`,
`class` и `instance`, а также `x`/`y`/`width`/`height` и необязательный `zOrder`.

#### 7.1.1 Выбор окон (одного или нескольких)

`--window` можно повторять, чтобы захватить **любое количество окон за один
вызов**. Каждый селектор интерпретируется автоматически (`--window-by auto`):

| Значение селектора     | Сопоставляется с                              |
| :---                   | :---                                          |
| `0`, `1`, …            | `index` из списка                             |
| `0x3c00007`            | `id` окна                                     |
| `VSCodium`             | `class` или `instance`, затем `title` (точно, затем по подстроке) |
| `Mark Shot - VSCodium` | `title`                                       |

Принудительно задайте одно правило сопоставления с помощью
`--window-by id|title|class|index`. Селектор, сопоставившийся с несколькими
окнами, захватывает **их все**.

Захват компонента (подобласти внутри окна) выполняется добавлением
`@x,y,width,height` к селектору — смещение задаётся относительно верхнего
левого угла окна и ограничивается границами окна:

```bash
# верхняя полоса высотой 100px окна 0
mark-shot --window "0@0,0,1680,100" --capture-destination file --capture-to /tmp/shots/
```

#### 7.1.2 Выбор места назначения изображений

`--capture-destination` определяет вывод; его можно сочетать с любым количеством
селекторов `--window` и подобластью-компонентом:

| Назначение | Поведение |
| :--- | :--- |
| `inline` (по умолчанию) | PNG в Base64, встроенные в JSON-вывод. **Файлы не записываются, буфер обмена не затрагивается.** Самый безопасный выбор для агентов, которым нужны только пиксели. |
| `file` | PNG-файлы записываются в `--capture-to <каталог>`; требует указания этой опции. |
| `stage` | PNG-файлы записываются во временный каталог подготовки (`$TMPDIR/mark-shot-staging`). Подходит для рабочего процесса «оставить на потом». |
| `clipboard` | Изображения копируются в системный буфер обмена; при нескольких изображениях побеждает **последнее**. Содержимое переживает завершение CLI (запускается постоянный владелец `wl-copy` / `xclip`). |

Примеры:

```bash
# несколько окон, сохранённые в каталог (по одному PNG на окно)
mark-shot --window VSCodium --window Terminal --capture-destination file --capture-to /tmp/shots/

# окно плюс компонент другого окна, отложенные на потом
mark-shot --window "VSCodium@0,0,400,300" --window 1 --capture-destination stage

# мультивыбор, возврат в base64 без обращения к файлам или буферу обмена
mark-shot --window 0 --window "Terminal" --capture-destination inline

# скопировать окно в буфер обмена
mark-shot --window 0 --capture-destination clipboard
```

**Политика буфера обмена.** Интерактивный редактор намеренно помещает ваш выбор
в системный буфер обмена (действие `Copy` / `Ctrl+C`), потому что это основной
рабочий процесс инструмента скриншотов. Безоконные режимы (CLI и корпоративный
MCP-сервер) следуют противоположному правилу: **буфер обмена никогда не
изменяется, если `clipboard` явно не выбран как назначение И запись в буфер
обмена включена в Настройки > Хранилище > Headless Mode** — `inline` (по
умолчанию) и `stage` не трогают текущее содержимое буфера обмена пользователя,
поэтому плановый или управляемый агентом захват не может перезаписать текст или
изображения, с которыми пользователь работает в другом месте. Когда запрос
`clipboard` отклоняется, потому что безоконная запись в буфер обмена отключена,
захват откатывается к настроенному безоконному назначению по умолчанию; об этом
сообщают JSON-вывод (`"warning"`) и stderr, а процесс завершается с ненулевым
кодом, чтобы автоматизация могла это обнаружить. Включение безоконной записи в
буфер обмена в настройках требует ввода подтверждающей парольной фразы.

Вывод — это JSON-объект `{"captures":[...]}` с одной записью на каждое
захваченное окно; каждая запись повторяет селектор, идентичность окна и
итоговый прямоугольник захвата, а также `path` (file/stage) или `data` (inline)
или ничего из этого (clipboard). Код выхода равен `0`, только если каждый
селектор сопоставился и каждый захват прошёл успешно; отсутствие совпадения или
неудачный захват дают код выхода `1` с полем `"error"` вместо тихого успеха.

Тот же конвейер захвата может программно создавать аннотированный вывод — см.
главу о MCP-сервере в корпоративной редакции или сочетайте сохранённый PNG с
интерактивным редактором.

#### 7.1.3 Гарантия отсутствия вмешательства в окна

Каждый безоконный режим гарантированно невидим и не мешает работе:

- **окно никогда не создаётся** — включая редактор аннотаций, оверлей захвата и
  трей; захват использует безоконный путь захвата;
- **диалог никогда не показывается** — включая диалоги ошибок: ошибки уходят в
  stderr; даже некорректные командные строки (например, `--window-by` без
  `--window`, неизвестный `--capture-destination` или лишние позиционные файлы)
  немедленно завершаются с ненулевым кодом и сообщением в stderr вместо
  всплывающего `QMessageBox` или перехода в интерактивный интерфейс;
- никакой интерактивный запрос портала не появляется
  (`allowInteractivePortal` отключён);
- процесс завершается сразу после записи вывода;
- список окон, захваченный до и после безоконной операции, идентичен;
- безоконные режимы никогда не касаются системного буфера обмена, если
  `clipboard` не был явно запрошен **и** запись в буфер обмена не включена в
  Настройки > Хранилище > Headless Mode.

Если окна не обнаружены (например, отключён помощник композитора или сеанс X11
без перечисления окон), команда выводит понятную ошибку в stderr и завершается
с кодом `1`, вместо того чтобы молча ничего не захватить.

## 8. Горячие клавиши рабочего стола и трей

Режим трея (`mark-shot --tray`) регистрирует `Ctrl+Alt+S` для захвата области и
предоставляет пункты меню захвата / записи / настроек / выхода. Горячие клавиши
рабочего стола:

- **GNOME**: Настройки → Клавиатура → Сочетания клавиш → Пользовательские
  сочетания → привязать к `mark-shot`.
- **KDE**: пользовательское сочетание, привязанное к `mark-shot` (плюс
  разрешение KWin ScreenShot2 для точного захвата в KDE, см. README).
- **Hyprland**: `bind = SUPER SHIFT, S, exec, mark-shot` и `bind = , Print, exec, mark-shot`.
- **niri**: `binds { Mod+Shift+S { spawn "mark-shot"; } }`.
- **Sway / i3**: `bindsym Mod4+Shift+S exec mark-shot`.

## 9. Конфигурация и бэкенды

- Файл конфигурации: `~/.config/mark-shot/config.json` (Linux), создаётся при
  первом запуске.
- Полный справочник: [Конфигурация](configuration.md).
- Бэкенды: Wayland (портал PipeWire / grim / screencopy wlroots), X11
  (`QScreen::grabWindow`), Windows (собственный WGC). Для записи предпочтителен
  портал PipeWire с автоматическим резервным вариантом.

Дополнительные помощники:

```bash
# OCR (RapidOCR / Tesseract)
python3 -m venv ~/.local/share/mark-shot/ocr-venv
~/.local/share/mark-shot/ocr-venv/bin/pip install -U pip rapidocr onnxruntime

# Сканирование кода (zxing-cpp)
python3 -m venv ~/.local/share/mark-shot/code-scan-venv
~/.local/share/mark-shot/code-scan-venv/bin/pip install -U pip zxing-cpp pillow
```

## 10. Контрольный список тестирования функций

Используйте его для сквозной проверки сборки:

1. **Запуск** — `run-mark-shot.sh` открывает замороженный оверлей.
2. **Наведение на окно** — переместите мышь над окном: бирюзовая рамка
   следует за курсором; одиночный щелчок выбирает окно; при перекрывающихся
   окнах выбирается самое верхнее.
3. **Ручная область** — перетащите прямоугольник; отпустите; откроется
   редактор.
4. **Аннотации** — рисуйте каждым инструментом (Перо, Линия, Прямоугольник,
   Эллипс, Стрелка, Маркер, Текст, Номер, Мозаика, Лупа, Лазер); отмена /
   повтор; Select для перемещения / масштабирования / поворота / удаления;
   двойной щелчок по тексту для редактирования.
5. **Копировать / Сохранить / Закрепить / Загрузить** — `Ctrl+C`, `Ctrl+S`,
   `Ctrl+P`, `Ctrl+U`.
6. **Стартовые инструменты** — `C` цветовая пипетка, `R` линейка, `Q`
   сканирование кода, `D` захват дисплея.
7. **Безоконный режим** — `--capture-to`, `--region`, `--display`,
   `--list-displays`.
8. **Безоконный захват окна** — `--list-windows` выводит список рабочего
   стола; повторяйте `--window`, чтобы захватить несколько окон; протестируйте
   `--capture-destination` во всех четырёх режимах (inline, file, stage,
   clipboard); проверьте селектор компонента (`--window "0@0,0,400,300"`);
   убедитесь, что список окон до и после не изменился (отсутствие вмешательства
   в окна).
9. **Трей + горячая клавиша** — `mark-shot --tray`, нажмите `Ctrl+Alt+S`.
10. **Особенности переносимого комплекта** — комплект находит собственные
    Qt-библиотеки / плагины / скрипты.
