# Mark Shot ユーザーガイド

このマニュアルでは、Mark Shot の日常的な操作について説明します。特に、**ウィンドウ / コンポーネントのホバー選択**機能（マウスを動かすとカーソル下のウィンドウを自動的に追跡してハイライトし、クリックで選択）、注釈ワークフロー、ヘッドレスキャプチャ、および設定に焦点を当てます。

> このリポジトリ内のドキュメントはコミュニティフォークで執筆され、アップストリームおよびエンタープライズリポジトリにもミラーリングされています。エンタープライズ版には、ローカル MCP サーバーに関する追加セクションがあります。

---

## 1. クイックスタート

### 1.1 起動

領域キャプチャセッションを開始します:

```bash
mark-shot
```

デスクトップのホットキー（§ 8 参照）を押すか、ターミナルから実行します。フォーカス中のディスプレイに全画面のフリーズオーバーレイが開きます。マウスを動かして選択矩形を描き、離すと注釈エディタに入ります。

### 1.2 ポータブルビルド

ポータブルバンドル（`mark-shot-upstream`、`mark-shot-community`、`mark-shot-enterprise`）を使用する場合は、バンドルされたランチャーで起動し、バンドルされた Qt ライブラリ、プラグイン、ヘルパースクリプトが見つかるようにしてください:

```bash
portable/mark-shot-community/bin/run-mark-shot.sh
```

ランチャーは自身の `bin/` ディレクトリを `PATH` の先頭に追加します。これはウィンドウ検出ヘルパースクリプト（`mark-shot-window-detection-*`）および OCR / アップロードヘルパーに必要です。

## 2. ウィンドウ / コンポーネントのホバー選択

Mark Shot は領域を選択する前に、現在のデスクトップのウィンドウを検出できます。選択オーバーレイを開いている間、**マウスを動かすとカーソル下のウィンドウがティール色のフレームでハイライト**されます。**通常の左クリック（ドラッグなし）でそのウィンドウ全体**をキャプチャ領域として選択できます。その後、そのまま注釈、コピー、ピン留め、保存ができます。

ハイライトされるウィンドウは、オーバーレイが表示される前に実行されるコンポジタごとの検出スクリプトによって取得されます:

| デスクトップ | 検出ソース | 備考 |
| :--- | :--- | :--- |
| GNOME Wayland | バンドルされた `mark-shot-scroll-helper@snemc.org` Shell 拡張機能（D-Bus 経由） | 拡張機能を有効にする必要があります（§ 2.1 参照） |
| KDE Plasma Wayland | `qdbus6` / `qdbus` + journalctl によるワンショット KWin スクリプティング | KWin セッションが必要です |
| Hyprland | `hyprctl -j clients` | |
| niri | `niri msg -j windows` + 設定の解析 | |
| X11 | `_NET_CLIENT_LIST_STACKING` のインプロセス XCB 列挙 | スクリプトは不要 |
| Windows | インプロセスの `EnumWindows` | スクリプトは不要 |

追跡されるのは**トップレベルウィンドウのみ**です。ウィンドウ内の個々のウィジェット（「コンポーネント」）は Wayland コンポジタでは公開されないため、ホバー選択はすべてのプラットフォームでウィンドウ全体を対象にします。

### 2.1 GNOME Wayland: ヘルパー拡張機能を有効にする

```bash
gnome-extensions enable mark-shot-scroll-helper@snemc.org
```

D-Bus ヘルパーが応答することを確認します:

```bash
gdbus call --session \
  --dest org.gnome.Shell \
  --object-path /org/gnome/Shell/Extensions/MarkShotScrollHelper \
  --method org.gnome.Shell.Extensions.MarkShotScrollHelper.Version
# -> ('5',)
```

呼び出しが失敗した場合は、ログアウトして再度ログインし（または X11 では GNOME Shell を再起動し）、再試行してください。拡張機能がない場合、GNOME ヘルパースクリプトはエラーで終了し、ホバー選択はオフのままになります（通常のドラッグ選択は引き続き動作します）。

### 2.2 使用方法

1. キャプチャを開始します（`mark-shot` またはデスクトップのホットキー）。
2. マウスボタンを押さずに、カーソルをウィンドウ上に移動します。選択されるウィンドウをティール色のフレームが囲みます。
3. **一度クリック**（数ピクセル以上動かさずに押して離す）するとそのウィンドウが選択されます。ウィンドウが重なっている場合は、カーソル位置の最前面のウィンドウが優先されます（z オーダー対応）。
4. 離すと、ウィンドウが正確にフレームされた状態で注釈エディタに入ります。
5. **手動**で領域を作るには、いつも通り矩形をドラッグするだけです。ドラッグがクリックしきい値を超えた時点でホバーフレームは無視されます。

ホバーハイライトは、Color Picker（`C`）または Ruler（`R`）の起動時ツールがアクティブな間は無効になり、Code Scanner（`Q`）、ディスプレイキャプチャ（`D`）、GIF / 動画録画の起動時モードでは引き続き利用できます。

### 2.3 正しいモニターでのウィンドウ選択

ウィンドウ検出はキャプチャ対象ごとに実行されます。マルチモニター環境では、各フリーズウィンドウは自身のジオメトリと交差するウィンドウのみを受け取るため、ホバーフレームはそのディスプレイで見えているものと一致します。

### 2.4 有効化 / 無効化

この機能はデフォルトで有効です（`windowDetection.enabled = true`）。**設定 → 詳細 → ウィンドウ検出を有効にする**で切り替えるか、`~/.config/mark-shot/config.json` を編集します:

```json
{
  "windowDetection": {
    "enabled": true,
    "command": "mark-shot-window-detection-gnome",
    "timeoutMs": 1000,
    "env": {}
  }
}
```

- `command`: 検出スクリプト。GNOME / KDE / Hyprland / niri Wayland では、セッションに一致するバンドル済みの `mark-shot-window-detection-*` スクリプトが自動的に選択されます。X11 と Windows ではプラットフォームがインプロセスで列挙され、`command` は空のままにできます。**ユーザーが指定したカスタムコマンド（例: 絶対パス）は常に尊重されます。**
- `timeoutMs`: スクリプトの最大待機時間（100〜30000 ms、デフォルトは 1000）。
- `env`: スクリプトに渡される追加の環境変数。コンポジタごとの調整（オフセット）はスクリプトのヘッダーに記載されています。

### 2.5 トラブルシューティング

| 症状 | 確認事項 |
| :--- | :--- |
| GNOME Wayland でティール色のフレームが出ない | 拡張機能が有効かどうか。上記の `gdbus` 呼び出しがバージョンを返す必要があります |
| X11 / Windows でティール色のフレームが出ない | なし — プラットフォーム列挙は組み込み済みです。キャプチャセッションが起動時ポインターツールを使用していないことを確認してください |
| ホバーフレームが（下の）誤ったウィンドウを選択する | カスタム検出スクリプトに z オーダーデータがない可能性があります。`zOrder` のないウィンドウは最下層として扱われます |
| キャプチャの開始が遅い | 検出スクリプトがオーバーレイの前に実行されます。デスクトップが遅い場合のみ `timeoutMs` を上げるか、`enabled:false` に設定してスキップしてください |
| 診断情報を見る | `mark-shot --debug --debug-log /tmp/mark-shot.log` を実行し、`window-detection` 行を確認してください |

## 3. 領域選択と起動時ツール

領域を確定する前に、起動時オーバーレイツールを使用できます:

| ホットキー | ツール | 動作 |
| :---: | :--- | :--- |
| `C` | Color Picker | ピクセルをサンプリングします。ホイールでルーペを拡大縮小します。左クリックでカラーパネル（HEX / RGB / HSL / HSV / Qt 形式）が開きます。右クリックまたは `Esc` で終了します |
| `R` | Ruler | ホバーでピクセル座標を読み取ります。左ドラッグで幅、高さ、対角線、面積を持つ矩形を測定します。右クリックまたは `Esc` で終了します |
| `Q` | Code Scanner | QR コード / バーコードの周囲をドラッグします。デコード結果はコピー可能なウィンドウで開きます |
| `D` | Display Capture | すべての出力をキャプチャし、ディスプレイごとにトリミングして、ホバー可能なサムネイル（コピー / 編集 / 保存）を表示します |
| `S` | アクティブな GIF / 動画録画を停止 | オーバーレイに表示されている録画を停止します |

`Esc` でセッションをキャンセルします。右クリック（起動時ツールなし）でもキャンセルできます。

## 4. 注釈ツール

領域を選択した後（またはローカル画像を開いた後）、注釈ツールバー付きのエディタが開きます。ツールは数字キーまたはツールバーで切り替えます:

| ホットキー | ツール | 説明 |
| :---: | :--- | :--- |
| `V` | Move / Pan | 選択全体を移動、ローカル画像キャンバスをパン |
| `S` | Select | 既存の注釈を選択、移動、拡大縮小、回転、削除 |
| `P` | Pen | 滑らかなフリーハンド描画 |
| `L` | Line | 直線 |
| `H` | Highlighter | 半透明のマーカー。フリーハンドまたは直線スタイル |
| `R` | Rectangle | `Stroke` / `Highlight` / `Invert` スタイルのボックス、角丸対応 |
| `E` | Ellipse | 楕円 / 円 |
| `A` | Arrow | クラシックな矢印（フェザリング付き、KDE、双方向） |
| `T` | Text | リッチテキスト。ホイールまたはスライダーでサイズ変更。対角ハンドルで両方向を拡大縮小、側面ハンドルで折り返しを調整。フォントパネルで正確な pt サイズ、フォントファミリー、太字 / 斜体を設定 |
| `N` | Number | 連番の番号マーカー（アラビア数字、アルファベット、ローマ数字、漢数字など） |
| `M` | Mosaic | 機密コンテンツを隠すためのアクリルぼかし |
| `G` | Laser | 自動的に消える一時的なストローク |

描画のヒント:

- 矩形 / 楕円を描くときに `Ctrl` を押し続けると、正方形 / 正円に制約されます。
- ツールがアクティブな状態でホイールをスクロールすると、ストローク幅、テキストサイズ、番号のスケール、またはモザイクのブロックサイズを調整できます（ライブプレビュー）。
- `Select` では、スクロールでキャンバスをズームし、中ボタンを押したままにするとパンできます。`Ctrl` をダブルタップでリセットします。

### 4.1 既存の注釈を編集する

**Select**（`S`）に切り替えます。注釈をクリックするとハンドルが表示されます:

- 内側をドラッグして移動;
- 角 / エッジのハンドルをドラッグしてサイズ変更;
- 上端の丸いハンドルをドラッグして回転;
- `Delete` / `Backspace` を押して削除;
- テキストをダブルクリックしてその場で編集。

プロパティパネル（右側）では、選択した注釈を編集できます: 色、幅、スタイル、テキストのフォントファミリー / サイズ / 太字 / 斜体。`Select` ツールで選択ボックスをドラッグすると複数の注釈を選択でき、グループ全体をまとめて移動、サイズ変更、回転、削除できます。

### 4.2 アクション

| ショートカット | アクション |
| :--- | :--- |
| `Ctrl+C` | クリップボードにコピー |
| `Ctrl+S` / `Enter` | 保存（設定のパステンプレートを使用） |
| `Ctrl+P` | フローティングステッカーウィンドウとしてピン留め |
| `Ctrl+U` | 設定された画像ホストにアップロード。URL がコピーされます |
| `Ctrl+Z` / `Ctrl+Y` | 元に戻す / やり直す |
| `F` | キャプチャ範囲を切り替え（選択範囲 ↔ 全画面） |

### 4.3 エクスポートフレーム

**設定 → エクスポート → Mac スタイルフレーム**を有効にすると、保存 / コピー / アップロードされた画像に透明なパディング、角丸、ソフトシャドウが追加されます。

## 5. ピン留めウィンドウステッカー

| ジェスチャー / ショートカット | 動作 |
| :--- | :--- |
| 左ドラッグ | ステッカーを再配置 |
| ホイール | 比率を保ったまま拡大縮小 |
| 左ダブルクリック / `Esc` | 閉じる |
| 右クリック | コンテキストメニュー（回転、ズーム、常に最前面、テキストをコピー、翻訳、保存、コピー、閉じる） |

ピン留めしたウィンドウ内の OCR テキストは選択・コピーできます（`Ctrl+C` / コンテキストメニュー）。翻訳（OpenAI 互換エンドポイント）は、翻訳されたテキストを元のレイアウト位置に画像へ描き戻します。

## 6. スクロールスクリーンショット

1. 領域を選択します（非常に大きな領域にはフローティングドラッグハンドルを使用できます）。
2. オーバーレイが対象ウィンドウをスクロールし、キャプチャしたフレームが長い画像に連結されます。
3. GNOME Wayland では Mark Shot Scroll Helper 拡張機能（§ 2.1）が必要です。

スクロールキャプチャは niri および同様の wlroots/Wayland コンポジタでは実運用に耐えます。KDE、X11、その他のスタックではテスト機能です。失敗した場合は、通常のスクリーンショットまたはカスタム拡張機能コマンドを使用してください。

## 7. ヘッドレスキャプチャ（CLI）

非対話型キャプチャは PNG を書き出し、JSON を出力します:

```bash
# primary screen
mark-shot --capture-to /tmp/shot.png

# directory (timestamped file name)
mark-shot --capture-to /tmp/shots/

# region
mark-shot --capture-to /tmp/r.png --region 0,0,1280,720

# a specific display, with cursor
mark-shot --capture-to /tmp/w.png --display DP-1 --include-cursor

# several displays at once (one PNG each)
mark-shot --capture-to /tmp/shots/ --display DP-1 --display DP-2

# list outputs
mark-shot --list-displays
```

すべてのヘッドレスオプションは、位置指定の画像ファイルとは相互排他的です。完全な引数テーブルは README を参照してください。

### 7.1 ヘッドレスのウィンドウ / コンポーネントキャプチャ

Mark Shot は、**UI を一切開かずに、特定のウィンドウ — またはウィンドウ内のコンポーネント（サブ領域）— をキャプチャ**できます。スクリプト、ビルドパイプライン、エージェントから使用できます。プロセスは画像が書き出されるか返されるとすぐに終了し、ウィンドウを作成せず、ダイアログを表示せず、フォーカスを奪うこともないため、ツールがデスクトップをキャプチャしている間もユーザーは作業を続けられます。

まず利用可能なウィンドウを一覧表示します:

```bash
mark-shot --list-windows
```

出力例（GNOME Wayland）:

```json
{"count":2,"platform":"wayland","source":"compositor-script","windows":[
  {"index":0,"id":"0x3c00007","title":"Mark Shot - VSCodium","class":"codium","instance":"codium","x":1920,"y":0,"width":1680,"height":1050,"zOrder":1},
  {"index":1,"title":"Terminal","class":"org.gnome.Terminal","x":67,"y":32,"width":800,"height":600}
]}
```

各エントリは、セレクタが照合するフィールドを保持しています: `index`、`id`（X11 ウィンドウ ID / バックエンド提供の ID）、`title`、`class`、`instance`、さらに `x`/`y`/`width`/`height` とオプションの `zOrder`。

#### 7.1.1 ウィンドウの選択（単一または複数）

`--window` は繰り返し指定でき、**1 回の呼び出しで任意の数のウィンドウをキャプチャ**できます。各セレクタは自動的に解釈されます（`--window-by auto`）:

| セレクタ値            | 一致対象                                             |
| :---                      | :---                                                |
| `0`, `1`, …               | リストの `index`                                        |
| `0x3c00007`               | ウィンドウ `id`                                         |
| `VSCodium`                | `class` または `instance`、次に `title`（完全一致、次に部分一致） |
| `Mark Shot - VSCodium`    | `title`                                             |

`--window-by id|title|class|index` で一致ルールを 1 つに固定します。複数のウィンドウに一致するセレクタは、**そのすべてをキャプチャ**します。

セレクタに `@x,y,width,height` を追加すると、ウィンドウ内のコンポーネント（サブ領域）をキャプチャできます。オフセットはウィンドウの左上隅からの相対位置で、ウィンドウ境界内にクランプされます:

```bash
# the top 100px strip of window 0
mark-shot --window "0@0,0,1680,100" --capture-destination file --capture-to /tmp/shots/
```

#### 7.1.2 画像の出力先を選択する

`--capture-destination` が出力先を決めます。任意の数の `--window` セレクタとコンポーネントのサブ領域と組み合わせることができます:

| 出力先 | 動作 |
| :--- | :--- |
| `inline`（デフォルト） | JSON 出力に埋め込まれた Base64 PNG。**ファイルは書き出されず、クリップボードにも一切触れません。** ピクセルだけを必要とするエージェントにとって最も安全な選択肢です。 |
| `file` | PNG ファイルが `--capture-to <directory>` に書き出されます。このオプションが必要です。 |
| `stage` | PNG ファイルが一時的なステージングディレクトリ（`$TMPDIR/mark-shot-staging`）に書き出されます。「後で使うために保存」というワークフローに適しています。 |
| `clipboard` | 画像がシステムクリップボードにコピーされます。複数の画像がある場合は**最後のものが優先**されます。コンテンツは CLI の終了後も残ります（永続的な `wl-copy` / `xclip` オーナーが起動されます）。 |

例:

```bash
# several windows, saved to a directory (one PNG per window)
mark-shot --window VSCodium --window Terminal --capture-destination file --capture-to /tmp/shots/

# a window plus a component of another window, staged for later
mark-shot --window "VSCodium@0,0,400,300" --window 1 --capture-destination stage

# multi-select, returned as base64 without touching files or clipboard
mark-shot --window 0 --window "Terminal" --capture-destination inline

# copy a window to the clipboard
mark-shot --window 0 --capture-destination clipboard
```

**クリップボードポリシー。** 対話型エディタは意図的に選択内容をシステムクリップボードに置きます（`Copy` アクション / `Ctrl+C`）。これはスクリーンショットツールの主要なワークフローだからです。ヘッドレスモード（CLI とエンタープライズ MCP サーバー）は逆のルールに従います: **`clipboard` が出力先として明示的に選択され、かつ設定の ストレージ > ヘッドレスモード でクリップボードへの書き込みが有効になっている場合を除き、クリップボードは変更されません** — `inline`（デフォルト）と `stage` はユーザーの現在のクリップボードの内容に触れないため、スケジュール実行やエージェント駆動のキャプチャがユーザーが他で作業中のテキストや画像を上書きすることはありません。ヘッドレスでのクリップボード書き込みが無効なために `clipboard` リクエストが拒否された場合、キャプチャは設定されたヘッドレスデフォルトの出力先にフォールバックし、JSON 出力（`"warning"`）と stderr がそれを通知し、プロセスは非ゼロの終了コードで終了するため、自動化で検出できます。設定でヘッドレスクリップボード書き込みを有効にするには、確認用のパスフレーズを入力する必要があります。

出力は JSON オブジェクト `{"captures":[...]}` で、キャプチャされたウィンドウごとに 1 エントリが含まれます。各エントリはセレクタ、ウィンドウの識別情報、最終的なキャプチャ矩形を繰り返し、さらに `path`（file/stage）または `data`（inline）、またはどちらでもない場合（clipboard）が含まれます。終了コードが `0` になるのは、すべてのセレクタが一致し、すべてのキャプチャが成功した場合のみです。一致しないものや失敗したキャプチャがあると、黙って成功する代わりに `"error"` フィールド付きで終了コード `1` になります。

同じキャプチャパイプラインで注釈付き出力をプログラム的に生成できます — エンタープライズ版の MCP サーバーの章を参照するか、保存した PNG を対話型エディタと組み合わせてください。

#### 7.1.3 ウィンドウ非干渉の保証

すべてのヘッドレスモードは、不可視かつ非妨害であることが保証されています:

- **ウィンドウは一切作成されません** — 注釈エディタ、キャプチャオーバーレイ、トレイも含みます。キャプチャはヘッドレスキャプチャパスを再利用します;
- **ダイアログは一切表示されません** — エラーダイアログも含みます。エラーは stderr に出力されます。不正なコマンドライン（例: `--window` のない `--window-by`、不明な `--capture-destination`、余分な位置指定ファイル）も、`QMessageBox` を表示したり対話型 UI にフォールバックしたりせず、stderr メッセージとともに非ゼロコードですぐに終了します;
- 対話型ポータルプロンプトは表示されません（`allowInteractivePortal` は無効）;
- プロセスは出力を書き出した後すぐに終了します;
- ヘッドレス操作の前後でウィンドウリストは同一です;
- ヘッドレスモードは、`clipboard` が明示的に要求された**かつ**設定の ストレージ > ヘッドレスモード でクリップボードへの書き込みが有効になっている場合を除き、システムクリップボードには一切触れません。

ウィンドウが検出されない場合（例: 無効化されたコンポジタヘルパー、またはウィンドウ列挙のない X11 セッション）、コマンドは黙って何もキャプチャせずに終了するのではなく、stderr に明確なエラーを出力してコード `1` で終了します。

## 8. デスクトップホットキーとトレイ

トレイモード（`mark-shot --tray`）は領域キャプチャ用に `Ctrl+Alt+S` を登録し、キャプチャ / 録画 / 設定 / 終了のメニュー項目を提供します。デスクトップホットキー:

- **GNOME**: 設定 → キーボード → ショートカット → カスタムショートカット → `mark-shot` にバインド。
- **KDE**: `mark-shot` にバインドしたカスタムショートカット（正確な KDE キャプチャ用の KWin ScreenShot2 権限が必要。README 参照）。
- **Hyprland**: `bind = SUPER SHIFT, S, exec, mark-shot` と `bind = , Print, exec, mark-shot`。
- **niri**: `binds { Mod+Shift+S { spawn "mark-shot"; } }`。
- **Sway / i3**: `bindsym Mod4+Shift+S exec mark-shot`。

## 9. 設定とバックエンド

- 設定ファイル: `~/.config/mark-shot/config.json`（Linux）。初回起動時に作成されます。
- 完全なリファレンス: [Configuration](configuration.md)。
- バックエンド: Wayland（PipeWire ポータル / grim / wlroots screencopy）、X11（`QScreen::grabWindow`）、Windows（ネイティブ WGC）。録画は PipeWire ポータルを優先し、自動的にフォールバックします。

オプションのヘルパー:

```bash
# OCR (RapidOCR / Tesseract)
python3 -m venv ~/.local/share/mark-shot/ocr-venv
~/.local/share/mark-shot/ocr-venv/bin/pip install -U pip rapidocr onnxruntime

# Code scan (zxing-cpp)
python3 -m venv ~/.local/share/mark-shot/code-scan-venv
~/.local/share/mark-shot/code-scan-venv/bin/pip install -U pip zxing-cpp pillow
```

## 10. 機能テストチェックリスト

ビルドをエンドツーエンドで検証するために使用します:

1. **起動** — `run-mark-shot.sh` でフリーズオーバーレイが開くこと。
2. **ウィンドウホバー** — ウィンドウ上にマウスを移動すると: ティール色のフレームが追従すること。シングルクリックでウィンドウが選択されること。重なっているウィンドウでは最前面のものが選択されること。
3. **手動領域** — 矩形をドラッグし、離すとエディタが開くこと。
4. **注釈** — 各ツール（Pen、Line、Rectangle、Ellipse、Arrow、Highlighter、Text、Number、Mosaic、Magnifier、Laser）で描画すること。元に戻す / やり直すこと。Select で移動 / サイズ変更 / 回転 / 削除すること。テキストをダブルクリックして編集すること。
5. **コピー / 保存 / ピン留め / アップロード** — `Ctrl+C`、`Ctrl+S`、`Ctrl+P`、`Ctrl+U`。
6. **起動時ツール** — `C` カラーピッカー、`R` ルーラー、`Q` コードスキャン、`D` ディスプレイキャプチャ。
7. **ヘッドレス** — `--capture-to`、`--region`、`--display`、`--list-displays`。
8. **ヘッドレスウィンドウキャプチャ** — `--list-windows` でデスクトップを一覧表示すること。`--window` を繰り返して複数のウィンドウをキャプチャすること。`--capture-destination` を 4 つのモードすべて（inline、file、stage、clipboard）でテストすること。コンポーネントセレクタ（`--window "0@0,0,400,300"`）を確認すること。前後でウィンドウリストが変わらないこと（ウィンドウ非干渉）を確認すること。
9. **トレイ + ホットキー** — `mark-shot --tray` を実行し、`Ctrl+Alt+S` を押すこと。
10. **ポータブル特有の確認** — バンドルが自身の Qt ライブラリ / プラグイン / スクリプトを見つけられること。
