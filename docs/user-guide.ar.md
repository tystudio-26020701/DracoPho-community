# دليل مستخدم Mark Shot

يغطي هذا الدليل عمليات الاستخدام اليومية لـ Mark Shot، مع التركيز على ميزة
**اختيار النافذة / المكوّن بالمرور فوقها** (تحريك الماوس يتبّع ويُبرِز النافذة
التي تحتها المؤشر تلقائيًا؛ والنقرة تختارها)، وسير عمل التعليقات التوضيحية،
والالتقاط بدون واجهة رسومية، والإعدادات.

> مستندات هذا المستودع كُتبت في النسخة المجتمعية (community fork) وتُنقل إلى
> المستودعات الأصلية (upstream) والمستودع الخاص بالمؤسسات. الإصدار المخصص
> للمؤسسات يضيف قسمًا إضافيًا لخادم MCP المحلي الخاص به.

---

## 1. البداية السريعة

### 1.1 التشغيل

ابدأ جلسة التقاط منطقة:

```bash
mark-shot
```

اضغط على اختصار سطح مكتب (انظر § 8) أو شغّله من الطرفية. تفتح طبقة تغطية
مجمّدة بملء الشاشة على الشاشة النشطة. حرّك الماوس لرسم مستطيل تحديد، ثم
أفلته للدخول إلى محرر التعليقات التوضيحية.

### 1.2 الإصدارات المحمولة

إذا كنت تستخدم حزمة محمولة (`mark-shot-upstream`, `mark-shot-community`,
`mark-shot-enterprise`)، شغّلها عبر أداة الإطلاق المرفقة حتى يتم العثور على
مكتبات Qt والملحقات والبرامج النصية المساعدة المرفقة:

```bash
portable/mark-shot-community/bin/run-mark-shot.sh
```

تضيف أداة الإطلاق دليل `bin/` الخاص بها إلى مقدمة `PATH`، وهو أمر مطلوب
للبرامج النصية المساعدة لاكتشاف النوافذ (`mark-shot-window-detection-*`)
والمساعدات الخاصة بـ OCR / الرفع.

## 2. اختيار النافذة / المكوّن بالمرور فوقها

يمكن لـ Mark Shot اكتشاف نوافذ سطح المكتب الحالي قبل أن تختار منطقة. أثناء
فتح طبقة التحديد، **تحريك الماوس يُبرِز النافذة الواقعة تحت المؤشر** بإطار
أخضر مزرق (teal). **نقرة يسرى عادية (بدون سحب) تختار النافذة بأكملها**
كمنطقة التقاط؛ ويمكنك بعد ذلك التعليق عليها أو نسخها أو تثبيتها أو حفظها مباشرة.

تأتي النوافذ المُبرَزة من برنامج نصي لاكتشاف حسب كل مُركِّب (compositor)
يعمل قبل ظهور طبقة التغطية:

| سطح المكتب | مصدر الاكتشاف | ملاحظات |
| :--- | :--- | :--- |
| GNOME Wayland | امتداد Shell المرفق `mark-shot-scroll-helper@snemc.org` عبر D-Bus | يتطلب تمكين الامتداد (انظر § 2.1) |
| KDE Plasma Wayland | برمجة KWin لمرة واحدة عبر `qdbus6` / `qdbus` + journalctl | يتطلب جلسة KWin |
| Hyprland | `hyprctl -j clients` | |
| niri | `niri msg -j windows` + تحليل الإعدادات | |
| X11 | تعداد XCB داخل العملية لـ `_NET_CLIENT_LIST_STACKING` | لا حاجة إلى برنامج نصي |
| Windows | `EnumWindows` داخل العملية | لا حاجة إلى برنامج نصي |

تُتتبع **نوافذ المستوى الأعلى فقط**. العناصر الفردية داخل النافذة
("المكوّنات") غير مكشوفة من قِبل مُركِّبات Wayland، لذا يستهدف اختيار
المرور النوافذ كاملة على كل المنصات.

### 2.1 GNOME Wayland: تفعيل امتداد المساعدة

```bash
gnome-extensions enable mark-shot-scroll-helper@snemc.org
```

تحقق من استجابة مساعد D-Bus:

```bash
gdbus call --session \
  --dest org.gnome.Shell \
  --object-path /org/gnome/Shell/Extensions/MarkShotScrollHelper \
  --method org.gnome.Shell.Extensions.MarkShotScrollHelper.Version
# -> ('5',)
```

إذا فشل الاستدعاء، سجّل الخروج ثم الدخول مجددًا (أو أعد تشغيل GNOME Shell على
X11) وحاول مجددًا. بدون الامتداد، يخرج البرنامج النصي المساعد لـ GNOME برسالة
خطأ ويبقى اختيار المرور معطّلًا (سحب التحديد العادي ما زال يعمل).

### 2.2 كيفية استخدامها

1. شغّل التقاطًا (`mark-shot` أو اختصار سطح المكتب).
2. دون الضغط على أي زر في الماوس، مرّر المؤشر فوق نافذة. سيظهر إطار أخضر
   مزرق حول النافذة التي سيتم تحديدها.
3. **انقر مرة واحدة** (اضغط وأفلت دون تحريك أكثر من بضعة بكسلات) لتحديد تلك
   النافذة. إذا تداخلت النوافذ، تفوز النافذة الأعلى ترتيبًا عند المؤشر
   (مراعيةً ترتيب z).
4. إفلات الزر يدخل إلى محرر التعليقات التوضيحية مع تأطير النافذة بدقة.
5. لإجراء منطقة **يدوية** بدلًا من ذلك، اسحب مستطيلًا كالمعتاد — يُتجاهل
   إطار المرور بمجرد أن يتجاوز السحب عتبة النقرة.

يُعطَّل تمييز المرور بينما تكون أداة بدء تشغيل Color Picker (`C`) أو Ruler
(`R`) نشطة، ويبقى متاحًا لأدوات Code Scanner (`Q`) والتقاط الشاشة (`D`)
ووضعي بدء تسجيل GIF / فيديو.

### 2.3 تحديد النوافذ على الشاشة الصحيحة

يعمل اكتشاف النوافذ لكل هدف التقاط. في إعداد متعدد الشاشات، تستقبل كل نافذة
مجمّدة النوافذ المتقاطعة مع هندستها الخاصة فقط، لذا يطابق إطار المرور ما تراه
على تلك الشاشة.

### 2.4 التفعيل / التعطيل

الميزة مفعّلة افتراضيًا (`windowDetection.enabled = true`). بدّل حالتها من
**Settings → Advanced → Window Detection Enabled**، أو عدّل
`~/.config/mark-shot/config.json`:

```json
{
  "windowDetection": {
    "enabled": true,
    "command": "mark-shot-window-detection-gnome",
    "timeoutMs": 1000,
    "env": {}
  }
}
```

- `command`: برنامج الاكتشاف النصي. على GNOME / KDE / Hyprland / niri لـ
  Wayland يُختار البرنامج النصي المرفق `mark-shot-window-detection-*`
  المطابق لجلسة عملك تلقائيًا؛ على X11 و Windows يُعدَّد النظام داخل العملية
  ويمكن ترك `command` فارغًا. **أمر مخصص يوفّره المستخدم (مثلًا مسار مطلق)
  يُحترم دائمًا.**
- `timeoutMs`: أقصى مدة انتظار للبرنامج النصي (100–30000 مللي ثانية، الافتراضي 1000).
- `env`: متغيرات بيئة إضافية تُمرَّر إلى البرنامج النصي. تعديلات خاصة بكل
  مُركِّب (الإزاحات) موثّقة في ترويسات البرامج النصية.

### 2.5 استكشاف الأخطاء وإصلاحها

| العرض | الفحص |
| :--- | :--- |
| لا إطار أخضر مزرق على GNOME Wayland | هل الامتداد مفعّل؟ يجب أن يُرجع استدعاء `gdbus` أعلاه إصدارًا |
| لا إطار أخضر مزرق على X11 / Windows | لا شيء — تعداد المنصة مدمج؛ تأكد من أن جلسة الالتقاط لا تستخدم أداة مؤشر عند بدء التشغيل |
| إطار المرور يلتقط نافذة خاطئة (الأسفل منها) | بيانات ترتيب z مفقودة من برنامج اكتشاف مخصص؛ النوافذ التي لا تحتوي `zOrder` تُرتَّب كطبقة سفلية |
| بدء الالتقاط بطيء | يعمل برنامج الاكتشاف قبل طبقة التغطية؛ ارفع `timeoutMs` فقط إذا كان سطح المكتب بطيئًا، أو اضبط `enabled:false` لتخطيه |
| راجع التشخيصات | شغّل `mark-shot --debug --debug-log /tmp/mark-shot.log`؛ وابحث عن سطور `window-detection` |

## 3. اختيار المنطقة وأدوات بدء التشغيل

قبل إتمام المنطقة يمكنك استخدام أدوات طبقة بدء التشغيل:

| الاختصار | الأداة | السلوك |
| :---: | :--- | :--- |
| `C` | Color Picker | عيّن بكسلًا؛ عجلة الماوس تعيد تحجيم العدسة المكبِّرة؛ النقرة اليسرى تفتح لوحة ألوان (صيغ HEX / RGB / HSL / HSV / Qt)؛ النقرة اليمنى أو `Esc` للخروج |
| `R` | Ruler | المرور يقرأ إحداثيات البكسل؛ السحب الأيسر يقيس مستطيلًا بالعرض والارتفاع والقطر والمساحة؛ النقرة اليمنى أو `Esc` للخروج |
| `Q` | Code Scanner | اسحب منطقة حول رمز QR / شريطي؛ تفتح النتيجة المفكَّكة في نافذة قابلة للنسخ |
| `D` | Display Capture | يلتقط كل المخرجات، يقصّ لكل شاشة، ويعرض صورًا مصغّرة تفاعلية (نسخ / تعديل / حفظ) |
| `S` | Stop active GIF / video recording | يوقف التسجيل المعروض في طبقة التغطية |

`Esc` يلغي الجلسة؛ والنقرة اليمنى (دون أداة بدء تشغيل) تلغي أيضًا.

## 4. أدوات التعليقات التوضيحية

بعد تحديد منطقة (أو فتح صورة محلية) يفتح المحرر مع شريط أدوات التعليقات
التوضيحية. تُبدَّل الأدوات بأزرار الأرقام أو عبر شريط الأدوات:

| الاختصار | الأداة | الوصف |
| :---: | :--- | :--- |
| `V` | Move / Pan | نقل التحديد كاملًا، وتحريك لوحة صورة محلية |
| `S` | Select | تحديد ونقل وقياس وتدوير وحذف التعليقات التوضيحية الموجودة |
| `P` | Pen | ضربات حرة ناعمة باليد |
| `L` | Line | خطوط مستقيمة |
| `H` | Highlighter | علامة شبه شفافة؛ بنمط يد حرة أو خط مستقيم |
| `R` | Rectangle | صندوق بأنماط `Stroke` / `Highlight` / `Invert`، بزوايا دائرية |
| `E` | Ellipse | قطع ناقص / دائرة |
| `A` | Arrow | أسهم تقليدية (ذات نصل، KDE، ثنائية الاتجاه) |
| `T` | Text | نص منسّق؛ العجلة أو المنزلقات تغيّر الحجم؛ مقابض القطر تُغيّر كلا الاتجاهين، والمقابض الجانبية تضبط الالتفاف؛ حجم بالنقطة بدقة، وعائلة الخط، وسميك / مائل في لوحة الخط |
| `N` | Number | علامات مرقّمة تسلسلية (عربية، أبجدية، رومانية، صينية، …) |
| `M` | Mosaic | ضبابية زجاجية مجمّدة (frost) لإخفاء المحتوى الحساس |
| `G` | Laser | ضربات مؤقتة تتلاشى تلقائيًا |

نصائح الرسم:

- اضغط مع الاستمرار `Ctrl` أثناء رسم مستطيل / قطع ناقص لتقييد الشكل على
  مربع / دائرة.
- مرّر عجلة الماوس أثناء تفعيل أداة لضبط عرض الخط، أو حجم النص، أو مقياس
  الأرقام، أو حجم كتلة الفسيفساء (معاينة حية).
- تحت أداة `Select`، مرّر العجلة لتكبير/تصغير اللوحة، واضغط مع الاستمرار على
  الزر الأوسط للتحريك؛ اضغط `Ctrl` مرتين سريعًا لإعادة الضبط.

### 4.1 تعديل تعليق توضيحي موجود

بدّل إلى **Select** (`S`). انقر على تعليق توضيحي لإظهار مقابضه:

- اسحب من الداخل للتحريك؛
- اسحب مقابض الزوايا / الحواف لتغيير الحجم؛
- اسحب المقبض الدائري أعلى الحافة العلوية للتدوير؛
- اضغط `Delete` / `Backspace` للحذف؛
- انقر مزدوجًا على نص لتعديله في مكانه.

لوحة الخصائص (الجانب الأيمن) تعدّل التعليق التوضيحي المحدد: اللون، والعرض،
والنمط، وعائلة خط النص / الحجم / السميك / المائل. يمكن تحديد تعليقات متعددة
بسحب صندوق تحديد تحت أداة `Select`؛ ويمكن بعدها تحريك المجموعة وتغيير حجمها
وتدويرها وحذفها معًا.

### 4.2 الإجراءات

| الاختصار | الإجراء |
| :--- | :--- |
| `Ctrl+C` | نسخ إلى الحافظة |
| `Ctrl+S` / `Enter` | حفظ (قالب المسار من الإعدادات) |
| `Ctrl+P` | تثبيت كنافذة ملصقة عائمة |
| `Ctrl+U` | رفع إلى مضيف الصور المضبوط؛ يُنسخ الرابط |
| `Ctrl+Z` / `Ctrl+Y` | تراجع / إعادة |
| `F` | تبديل نطاق الالتقاط (التحديد ↔ ملء الشاشة) |

### 4.3 إطار التصدير

فعّل **Settings → Export → Mac-style frame** لإضافة هامش شفاف وزوايا دائرية
وظلًا ناعمًا إلى الصور المحفوظة / المنسوخة / المرفوعة.

## 5. ملصقات النوافذ المثبَّتة

| الإيماءة / الاختصار | السلوك |
| :--- | :--- |
| السحب الأيسر | إعادة وضع الملصق |
| العجلة | قياس نسبي |
| نقرة يسرى مزدوجة / `Esc` | إغلاق |
| النقرة اليمنى | قائمة سياق (تدوير، تكبير، في المقدمة دائمًا، نسخ نص، ترجمة، حفظ، نسخ، إغلاق) |

نص OCR داخل نافذة مثبَّتة قابل للتحديد والنسخ (`Ctrl+C` / قائمة السياق).
الترجمة (نقطة نهاية متوافقة مع OpenAI) تعيد عرض النص المترجم على الصورة في
مواضع التخطيط الأصلية.

## 6. لقطة الشاشة الممتدّة (التمرير)

1. حدد منطقة (أو استخدم مقبض السحب العائم للمناطق الكبيرة جدًا).
2. تمرّر طبقة التغطية نافذة الهدف؛ وتُخاط الصور الملتقطة في صورة طويلة.
3. يتطلب GNOME Wayland امتداد Mark Shot Scroll Helper (§ 2.1).

الالتقاط الممتدّ جاهز للإنتاج على niri ومُركِّبات wlroots/Wayland المماثلة؛
على KDE و X11 والأنظمة الأخرى فهو ميزة قيد الاختبار. إذا فشل، استخدم لقطات
الشاشة العادية أو أمر امتداد مخصص.

## 7. الالتقاط بدون واجهة رسومية (سطر الأوامر)

يكتب الالتقاط غير التفاعلي ملف PNG ويطبع JSON:

```bash
# primary screen
mark-shot --capture-to /tmp/shot.png

# directory (timestamped file name)
mark-shot --capture-to /tmp/shots/

# region
mark-shot --capture-to /tmp/r.png --region 0,0,1280,720

# a specific display, with cursor
mark-shot --capture-to /tmp/w.png --display DP-1 --include-cursor

# several displays at once (one PNG each)
mark-shot --capture-to /tmp/shots/ --display DP-1 --display DP-2

# list outputs
mark-shot --list-displays
```

جميع خيارات الالتقاط بدون واجهة متنافية مع ملف صورة موضعي.
راجع README لجدول الوسائط الكامل.

### 7.1 التقاط نافذة / مكوّن بدون واجهة رسومية

يمكن لـ Mark Shot التقاط **نوافذ محددة — أو مكوّن (منطقة فرعية) داخل
نافذة — دون فتح أي واجهة مستخدم**، من برنامج نصي أو خط بناء أو وكيل (agent).
تخرج العملية بمجرد كتابة الصور أو إرجاعها، ولا تُنشئ نافذة أبدًا، ولا تُظهر
حوارًا أبدًا، ولا تسرق التركيز أبدًا، فيمكن للمستخدم مواصلة العمل بينما
تلتقط أداة ما سطح المكتب.

أولًا اسرد النوافذ لمعرفة المتاح:

```bash
mark-shot --list-windows
```

مثال على المخرجات (GNOME Wayland):

```json
{"count":2,"platform":"wayland","source":"compositor-script","windows":[
  {"index":0,"id":"0x3c00007","title":"Mark Shot - VSCodium","class":"codium","instance":"codium","x":1920,"y":0,"width":1680,"height":1050,"zOrder":1},
  {"index":1,"title":"Terminal","class":"org.gnome.Terminal","x":67,"y":32,"width":800,"height":600}
]}
```

يحمل كل إدخال الحقول التي تطابقها المُحدِّدات: `index`, `id`
(معرّف نافذة X11 / معرّف يوفّره النظام الخلفي), `title`, `class` و `instance`,
بالإضافة إلى `x`/`y`/`width`/`height` و `zOrder` اختياريًا.

#### 7.1.1 تحديد النوافذ (واحدة أو عدة)

يمكن تكرار `--window` لالتقاط **أي عدد من النوافذ في استدعاء واحد**.
يُفسَّر كل مُحدِّد تلقائيًا (`--window-by auto`):

| قيمة المُحدِّد | ما يطابقه |
| :--- | :--- |
| `0`, `1`, … | `index` من القائمة |
| `0x3c00007` | `id` النافذة |
| `VSCodium` | `class` أو `instance`, ثم `title` (مطابق تام، ثم نص فرعي) |
| `Mark Shot - VSCodium` | `title` |

فرض قاعدة مطابقة واحدة عبر `--window-by id|title|class|index`. المُحدِّد
الذي يطابق عدة نوافذ يلتقط **كلّها**.

التقط مكوّنًا (منطقة فرعية داخل نافذة) بإلحاق
`@x,y,width,height` بالمُحدِّد — الإزاحة نسبية للزاوية العلوية اليسرى
للنافذة وتُقيَّد بحدود النافذة:

```bash
# the top 100px strip of window 0
mark-shot --window "0@0,0,1680,100" --capture-destination file --capture-to /tmp/shots/
```

#### 7.1.2 اختيار وجهة الصور

يحدد `--capture-destination` وجهة الإخراج؛ ويمكن دمجه مع أي عدد من
مُحدِّدات `--window` ومنطقة مكوّن فرعية:

| الوجهة | السلوك |
| :--- | :--- |
| `inline` (الافتراضية) | صور PNG بصيغة Base64 مضمّنة في مخرجات JSON. **لا تُكتب أي ملفات ولا تُلمَس الحافظة أبدًا.** الخيار الأكثر أمانًا للوكلاء الذين يريدون البكسلات فقط. |
| `file` | تُكتب ملفات PNG إلى `--capture-to <directory>`؛ يتطلب هذا الخيار. |
| `stage` | تُكتب ملفات PNG إلى دليل مراحل مؤقت (`$TMPDIR/mark-shot-staging`). مناسبة لسير عمل "احتفظ به لاحقًا". |
| `clipboard` | تُنسخ الصور إلى حافظة النظام؛ مع عدة صور **تفوز الأخيرة**. يبقى المحتوى بعد خروج CLI (يُطلق مالك دائم `wl-copy` / `xclip`). |

أمثلة:

```bash
# several windows, saved to a directory (one PNG per window)
mark-shot --window VSCodium --window Terminal --capture-destination file --capture-to /tmp/shots/

# a window plus a component of another window, staged for later
mark-shot --window "VSCodium@0,0,400,300" --window 1 --capture-destination stage

# multi-select, returned as base64 without touching files or clipboard
mark-shot --window 0 --window "Terminal" --capture-destination inline

# copy a window to the clipboard
mark-shot --window 0 --capture-destination clipboard
```

**سياسة الحافظة.** يضع المحرر التفاعلي تحديدك عمدًا على حافظة النظام (إجراء
`Copy` / `Ctrl+C`)، لأن هذا هو سير العمل الأساسي لأداة لقطات شاشة. تتبع
الأوضاع بدون واجهة (سطر الأوامر وخادم MCP الخاص بالمؤسسات) القاعدة المعاكسة:
**لا تُعدَّل الحافظة أبدًا ما لم تُختَر `clipboard` صراحةً كوجهة، وعمليات
الكتابة في الحافظة مفعّلة في Settings > Storage > Headless Mode** —
يتركان `inline` (الافتراضي) و `stage` محتوى حافظة المستخدم الحالي دون
مساس، فلا يمكن لالتقاط مجدول أو موجَّه من وكيل أن يكتب فوق نصوص أو صور
يعمل عليها المستخدم في مكان آخر. عندما يُرفض طلب `clipboard` لأن كتابة
الحافظة بدون واجهة معطّلة، يتراجع الالتقاط إلى وجهة الالتقاط الافتراضية
الخاصة بالأوضاع بدون واجهة، ويخبرك مخرجا JSON (`"warning"`) و stderr
بذلك، وتخرج العملية برمز خروج غير صفري حتى تستطيع الأتمتة اكتشافه. يتطلب
تفعيل كتابة الحافظة بدون واجهة في الإعدادات إدخال عبارة تأكيد.

المخرجات كائن JSON `{"captures":[...]}` بإدخال واحد لكل نافذة ملتقطة؛ يكرر
كل إدخال المُحدِّد وهوية النافذة ومستطيل الالتقاط النهائي، بالإضافة إلى `path`
(ملف/مرحلة) أو `data` (مضمّن) أو لا شيء منهما (حافظة). يكون رمز الخروج `0`
فقط عندما يطابق كل مُحدِّد وينجح كل التقاط؛ أما المطابقة المفقودة أو الالتقاط
الفاشل فيعطي رمز خروج `1` مع حقل `"error"` بدل النجاح الصامت.

يمكن لخط الالتقاط نفسه إنتاج مخرجات مُعلَّقة برمجيًا — راجع فصل خادم MCP في
الإصدار المخصص للمؤسسات، أو ادمج PNG المحفوظ مع المحرر التفاعلي.

#### 7.1.3 ضمان عدم التداخل مع النوافذ

يُضمن أن كل وضع بدون واجهة غير مرئي وغير مُزعِج:

- **لا تُنشأ أي نافذة أبدًا** — بما فيها محرر التعليقات التوضيحية، وطبقة
  الالتقاط، والعلبة (tray)؛ يعيد الالتقاط استخدام مسار الالتقاط بدون واجهة؛
- **لا يُعرض أي حوار أبدًا** — بما فيها حوارات الأخطاء: تذهب الأخطاء إلى
  stderr؛ حتى أسطر الأوامر المعطوبة (مثلًا `--window-by` دون `--window`،
  أو `--capture-destination` غير معروف، أو ملفات موضعية زائدة) تخرج فورًا
  برمز غير صفري ورسالة على stderr بدل إظهار `QMessageBox` أو النزول إلى
  واجهة المستخدم التفاعلية؛
- لا تظهر أي مطالبة بوابة تفاعلية (`allowInteractivePortal` معطّلة)؛
- تخرج العملية فورًا بعد كتابة المخرجات؛
- قائمة النوافذ الملتقطة قبل عملية بدون واجهة وبعدها متطابقة؛
- لا تلمس الأوضاع بدون واجهة حافظة النظام أبدًا ما لم تُطلَب `clipboard`
  صراحةً **و** كانت كتابة الحافظة مفعّلة في
  Settings > Storage > Headless Mode.

إذا لم تُكتشف أي نوافذ (مثلًا مساعد مُركِّب معطّل، أو جلسة X11 دون تعداد
نوافذ)، يطبع الأمر رسالة خطأ واضحة على stderr ويخرج بالرمز `1` بدل التقاط
لا شيء بصمت.

## 8. اختصارات سطح المكتب والعلبة

يسجّل وضع العلبة (`mark-shot --tray`) اختصار `Ctrl+Alt+S` لالتقاط منطقة
ويوفّر عناصر قائمة للالتقاط / التسجيل / الإعدادات / الخروج. اختصارات سطح
المكتب:

- **GNOME**: Settings → Keyboard → Shortcuts → Custom Shortcuts → اربطه بـ `mark-shot`.
- **KDE**: اختصار مخصص مربوط بـ `mark-shot` (إضافة إلى إذن KWin ScreenShot2
  للالتقاط الدقيق على KDE، انظر README).
- **Hyprland**: `bind = SUPER SHIFT, S, exec, mark-shot` و `bind = , Print, exec, mark-shot`.
- **niri**: `binds { Mod+Shift+S { spawn "mark-shot"; } }`.
- **Sway / i3**: `bindsym Mod4+Shift+S exec mark-shot`.

## 9. الإعدادات والأنظمة الخلفية

- ملف الإعدادات: `~/.config/mark-shot/config.json` (لينكس)، يُنشأ عند أول تشغيل.
- المرجع الكامل: [Configuration](configuration.md).
- الأنظمة الخلفية: Wayland (بوابة PipeWire / grim / wlroots screencopy)، X11
  (`QScreen::grabWindow`)، Windows (WGC الأصلي). يفضّل التسجيل بوابة
  PipeWire ويتراجع تلقائيًا.

مساعدات اختيارية:

```bash
# OCR (RapidOCR / Tesseract)
python3 -m venv ~/.local/share/mark-shot/ocr-venv
~/.local/share/mark-shot/ocr-venv/bin/pip install -U pip rapidocr onnxruntime

# Code scan (zxing-cpp)
python3 -m venv ~/.local/share/mark-shot/code-scan-venv
~/.local/share/mark-shot/code-scan-venv/bin/pip install -U pip zxing-cpp pillow
```

## 10. قائمة فحص اختبار الميزات

استخدمها للتحقق من إصدار من النهاية إلى النهاية:

1. **Launch** — `run-mark-shot.sh` يفتح طبقة التغطية المجمّدة.
2. **Window hover** — مرّر الماوس فوق نافذة: يتبعها إطار أخضر مزرق؛ النقرة
   المفردة تحدد النافذة؛ النوافذ المتداخلة تختار الأعلى منها.
3. **Manual region** — اسحب مستطيلًا؛ أفلت؛ يفتح المحرر.
4. **Annotate** — ارسم بكل أداة (Pen, Line, Rectangle, Ellipse, Arrow,
   Highlighter, Text, Number, Mosaic, Magnifier, Laser)؛ تراجع/إعادة؛ وSelect
   للتحريك/تغيير الحجم/التدوير/الحذف؛ انقر مزدوجًا على نص لتعديله.
5. **Copy / Save / Pin / Upload** — `Ctrl+C`, `Ctrl+S`, `Ctrl+P`, `Ctrl+U`.
6. **Startup tools** — `C` منتقي الألوان، `R` المسطرة، `Q` فحص الكود، `D`
   التقاط الشاشة.
7. **Headless** — `--capture-to`, `--region`, `--display`, `--list-displays`.
8. **Headless window capture** — `--list-windows` يسرد سطح المكتب؛ كرر
   `--window` لالتقاط عدة نوافذ؛ اختبر `--capture-destination` في كل
   الأوضاع الأربعة (inline, file, stage, clipboard)؛ تحقق من مُحدِّد مكوّن
   (`--window "0@0,0,400,300"`)؛ أكّد أن قائمة النوافذ قبل وبعد لم تتغير
   (عدم التداخل مع النوافذ).
9. **Tray + hotkey** — `mark-shot --tray`، اضغط `Ctrl+Alt+S`.
10. **Portable specifics** — تجد الحزمة مكتبات Qt/مكوناتها الإضافية/برامجها النصية الخاصة.
